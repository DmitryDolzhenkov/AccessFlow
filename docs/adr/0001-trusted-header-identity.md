# Идентификация вызывающего через доверенный заголовок X-User-Id

Полноценный authentication provider вне scope, поэтому личность вызывающего передаётся заголовком `X-User-Id`, который ссылается на заранее заведённого User; подлинность заголовка не проверяется. Аутентификация — сознательная заглушка, но авторизация настоящая: право действовать над Access Request (например, решение принимает только System Owner) проверяется в домене, а не в контроллерах.

## Consequences

Любой, кто может достучаться до API, может представиться любым User. Система допустима только во внутреннем доверенном контуре; замена на реальный провайдер должна менять лишь способ получения идентификатора User, не доменные проверки.
