# Асинхронный Provisioning через outbox и фоновый обработчик в процессе

Одобрение Access Request фиксируется в PostgreSQL в той же транзакции, что и outbox-запись о необходимости Provisioning; HTTP-вызов в System выполняет `BackgroundService` в том же процессе, с повторами. Мы отказались от синхронного вызова внутри операции одобрения, чтобы одобрение не терялось и не откатывалось из-за недоступности System и чтобы в транзакции не было сетевых вызовов; брокер сообщений исключён архитектурными ограничениями.

## Consequences

Одобрение и Provisioning — разные моменты времени, поэтому у Access Request есть состояния между «одобрена» и «доступ выдан». Вызов в System может повториться, поэтому интеграция должна быть идемпотентной.
